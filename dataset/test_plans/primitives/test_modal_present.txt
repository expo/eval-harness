<purpose>
Primitive: Navigation → Modal presentation → Modal present (APP-AGNOSTIC).
Verify that an action which the PRD specifies should present a confirmation / warning modal does in fact present one, with the expected structural pieces: a dialog overlay, messaging conveying the action's consequence, and at least two action affordances (typically a confirm and a cancel/dismiss).

This test plan is APP-AGNOSTIC. Use the supplied App PRD to determine which action in this app should present a modal — typical examples: deleting a record, logging out, leaving an in-progress game, "are you sure" warnings, or "low data / cannot proceed" warnings.
</purpose>

<seeding_and_precondition>
Read the supplied App PRD to determine a MODAL-TRIGGERING ACTION that this app exposes. Common patterns:

- A destructive action that requires confirmation (delete a record, end a session, log out, cancel a booking).
- A guard or warning that appears under an edge condition (PRD-specified "warning" or "are you sure" prompts).
- A confirmation before a billing or commitment step.

Pick the SIMPLEST modal-triggering action specified in the PRD — ideally a destructive confirmation for a record the agent can create and then delete in setup. Avoid actions that require external dependencies (network calls, third-party services) or multi-step preconditions.

Setup for the formal test:
- Navigate to whichever screen the modal-triggering action is reachable from.
- Create or seed any record / state that the action needs to operate on (e.g., create a note in order to delete it; create a flight in order to delete it).
- The formal test then triggers the action and verifies the modal's structure. Do NOT confirm the destructive action — only trigger the modal and verify it, then dismiss via the cancel/close affordance at the end so the underlying state remains intact.

If the PRD indicates the app has no modal-presenting actions at all (no confirmations, no warnings, no destructive-action guards), record this primitive as not-applicable and immediately call complete_step with the note "N/A: PRD indicates app has no modal-presenting actions."
</seeding_and_precondition>
